# Deep Read Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Swipe left on any feed card → the whole story, AI-written in easy language, paginated like a newspaper; generated on first open, cached in `stories.deep_read` forever after.

**Architecture:** A Supabase Edge Function `deepread` (mirroring `qa`'s Groq-first lane pattern) builds context from the story row + cluster corroboration + a bounded article fetch, produces validated `{"pages":[{heading,body}...]}` JSON, saves it to the new `stories.deep_read jsonb` column, and returns it. The Flutter feed wraps each card in a horizontal PageView: page 0 is the card, pages 1..N are the deep read, with a "writing…" state on first open.

**Tech Stack:** Deno edge function (no new npm deps beyond `@supabase/supabase-js` already used by `qa`), Flutter (no new packages), PostHog `track` (exists).

## Global Constraints

- Facts only, never advice; easy language; never invent numbers not present in the context (spec).
- Contract verbatim: `{"pages": [{"heading": <string|null>, "body": <string>}]}` — 1–8 pages, every body non-empty; anything else is a refusal `{"pages": []}`, which is returned but **never cached**.
- GNews wrapper URLs (`news.google.com`) are never fetched for article context (JS-locked, verified 2026-08-12).
- Groq-first lanes; chat must never touch the pipeline's Gemini pool except as last-resort depth (same posture as `qa`).
- No new Flutter dependencies; clay-black newspaper dress: serif headings, 16.5px serif body, mono metadata, page dots.
- The write to `stories.deep_read` happens only via the edge function's service role; RLS is untouched.
- Analytics: `track('deep_read', {'story_id': id})` fires on first horizontal open of a story (not per page).

```dart
/// One newspaper page of a deep read (spec 2026-08-16).
class DeepPage {
  final String? heading;
  final String body;
  DeepPage(this.heading, this.body);
}

/// The AI-written whole story. Every field defaults so a refusal or a
/// truncated payload degrades to "no pages" instead of throwing.
class DeepRead {
  final List<DeepPage> pages;
  DeepRead(this.pages);
  bool get hasContent => pages.isNotEmpty;

  factory DeepRead.fromJson(Map<String, dynamic>? j) {
    final raw = j?['pages'];
    if (raw is! List) return DeepRead(const []);
    return DeepRead([
      for (final p in raw)
        if (p is Map && (p['body'] is String) && (p['body'] as String).trim().isNotEmpty)
          DeepPage(p['heading'] as String?, p['body'] as String)
    ]);
  }
}
```

### Task 2: edge function `deepread`

**Files:**
- Create: `supabase/functions/deepread/index.ts`

**Interfaces:**
- Consumes: `stories.deep_read` column (Task 1's migration), `chat()`-style lanes from qa.
- Produces: HTTP POST `{story_id: number}` → `{"pages": [...]}` (contract above). Task 3 calls it via `Supabase.instance.client.functions.invoke('deepread', body: {'story_id': id})`.

- [ ] **Step 1: Implement** — structure (transcribe qa's `lanes()`/`chat()` verbatim, then):

```ts
// Deep read (spec 2026-08-16): the whole story, written once, cached forever.
// POST {story_id} -> {"pages":[{heading,body}...]}; {"pages":[]} = refusal,
// returned but never cached so a later open retries.
```

1. Parse `story_id` (integer; else 400).
2. `select id, headline, hook, summary, category, impact_score, source_url, cluster_id, deep_read from stories where id = eq.<id>` (single row; 404 if absent).
3. If `deep_read` non-null → return it immediately.
4. Context: cluster members `select headline, source_name, source_url from stories where cluster_id = eq.<cid> limit 12`; article body: pick the row's own `source_url` unless it contains `news.google.com`, else the first member URL without it; fetch with 5s AbortController timeout, `text()`, strip tags `replace(/<script[\s\S]*?<\/script>/gi,'').replace(/<style[\s\S]*?<\/style>/gi,'').replace(/<[^>]+>/g,' ')`, collapse whitespace, slice 6000 chars; ANY failure → empty string.
5. Prompt (JSON mode):

```
You are FinSwipe's staff writer. Using ONLY the material below, write the
whole story for a reader who knows nothing about it, in plain easy English.
Facts only, never advice, never numbers that are not in the material.
Structure it as 3-6 newspaper pages, each 60-120 words:
"What happened", "Background", "Who is affected", "Why it matters",
and "What's next" only if the material supports it.
If the material is too thin to write honestly, return {"pages": []}.
Return ONLY JSON: {"pages": [{"heading": "...", "body": "..."}]}

HEADLINE: ... / HOOK: ... / SUMMARY: ...
CATEGORY: ... IMPACT: .../10
ALSO REPORTED BY: <member headlines + outlets, one per line>
ARTICLE TEXT: <fetched text or "(unavailable)">
```

6. Validate: parse JSON; keep pages where body is a non-empty string; cap 8; if 0 → return `{"pages": []}` **without caching**.
7. Cache: `PATCH stories?id=eq.<id>` body `{deep_read: validated}` via service client.
8. Return validated JSON, `Content-Type: application/json`, CORS headers copied from qa's response shape.
